# Manual Review Protocol

Step-by-step procedure for human reviewers turning claims into canonical
values. Reviewers work from **review packets** (`data/review_packets/`,
generated by `packets.py`).

## 1. Reviewer identity

Every decision records a `reviewer` identity (required, non-empty). Automated
processes are never a reviewer identity. **STATUS: PROPOSED:** reviewers use
stable pseudonymous handles registered internally; whether a second reviewer
is required before `publishable` is open question #9.

## 2. Review workflow per incident

1. **Identity check** — is this one incident (research protocol §1)? Check
   duplicate candidates flagged by QC; merge only via `incident_merge_log`.
2. **Scope check** — apply `inclusion_exclusion_rules.md`; set
   `incident_status` + `scope_rationale`.
3. **Field-by-field decisions** — for each publication-critical field
   (`incident_start_datetime`, `province_code`, `fatalities_current`) and any
   contested field: inspect all claims, record one decision
   (`accept_claim` / `manual_override` / `reject_field` / `defer`) with
   rationale, per `conflict_resolution_protocol.md`.
4. **Casualty observations** — confirm exactly one `is_current_canonical`
   observation; revisions are new rows.
5. **Classifications** — verify all four-axis rows are source-backed before
   marking `reviewed` (cause coding protocol §2).
6. **Organization roles** — apply the defamation guardrails
   (`editorial_and_legal_protocol.md` §2).
7. **Location** — verify precision category; apply the informal-operation
   coordinate restraint (privacy protocol §5).
8. **Sign-off** — set `verification_status = 'reviewed'`; editorial
   `publication_status = 'publishable'` is a separate, deliberate act.

## 3. AI/OCR-assisted claims

Claims created with `extraction_method` in (`ai_assisted`, `ocr_assisted`)
arrive as `needs_review`. The reviewer must verify the extraction against the
raw document before marking `reviewed`. **Unreviewed AI/OCR claims can never
be selected as canonical** — the schema and QC enforce this; the reviewer's
job is the verification itself.

## 4. What reviewers never do

- Edit canonical values by hand (promotion is application code only).
- Delete or modify claims, source documents, or past decisions.
- Resolve conflicts without a recorded rationale.
- Insert knowledge from memory without a source document behind a claim.

## 5. Audit trail

Every material action lands in `review_log` (actor, action, entity,
before/after summaries, timestamp). The log is append-only.
